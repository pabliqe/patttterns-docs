# Cache Pipeline (Notion + Search + Build Artifacts)

This document explains how cache and generated artifacts move through the build pipeline in this repository.

## Why This Exists

The project separates **content generation** (local, before commit) from **site build** (Netlify, on push):

- reduce Notion API pressure during static generation
- avoid rate-limit bursts (429) in production builds
- keep search/navigation data static and fast at runtime
- generate redirect maps once per deploy, then serve them at edge/CDN speed

Static export exists because rendering Notion on Netlify Functions was too costly. Visitors never hit Notion; Netlify only reads committed artifacts.

## Official vs unofficial Notion API

| | Official | Unofficial (page bodies) |
|--|----------|--------------------------|
| Host | `api.notion.com/v1` | `app.notion.com/api/v3` (via `notion-client`) |
| Auth | `NOTION_API_KEY` (Connection / integration) | `NOTION_TOKEN` (`token_v2` cookie) |
| Used by | `build:search`, `build:metadata`, optional component Notion patches | `build:content`, local `next dev` page fetch |
| Writes | `search-index.json`, components metadata | `public/.notion-cache/*.json` (recordMaps for react-notion-x) |

Netlify `prebuild` / `next build` call **neither** API.

Shared unofficial client options live in [`notion-private-api.mjs`](../../../notion-private-api.mjs): non-empty `User-Agent` + `app.notion.com` base URL. Required since Aug 2026 when Cloudflare began blocking Node requests without a UA ([react-notion-x#710](https://github.com/NotionX/react-notion-x/issues/710)).

## Two Pipelines

### 1) Content publish (local only)

Run when Notion content changes:

```bash
npm run publish:content
```

Order (from `scripts/publish-content.mjs`):

1. `npm run build:search` — **official**
2. `npm run build:metadata` — **official** + Gemini (incremental, no `--force`)
3. `npm run build:shell` — `build:search` + `build:content -- --refresh-shell` (index, new pages, homepage/category shells)
4. `npm run validate:content-cache` — index vs `.notion-cache`
5. `npm run build:artifacts` — official patches optional + Gemini
6. `npm run validate:artifacts` — report
7. `npm run build:og-images` — GIF/Giphy social covers → static JPEG cards
8. `npm run components:seeds:upload` — ship **new** seeds to Netlify Blobs (`seed_exists` skipped; `--ids=<id> --force` overwrites one seed and keeps `vN`)

Commit local outputs, then push. Runtime Export/Preview reads Blobs (git TSX is stripped from `out/`). See [Publishing Notion Content](CRON_SETUP) and [Components Seeds Pipeline](../components-seeds-pipeline).

### 2) Site prebuild (every `npm run build`, including Netlify)

From `package.json` `prebuild` hook — **no Notion fetches**, **no OG cover generation**:

1. `npm run validate:content-cache` — fail if `search-index.json` lists a page with no `public/.notion-cache/{id}.json`
2. `npm run build:redirects`
3. `npm run build:edge-data`
4. `npm run validate:redirects`
5. `npm run build:mcp-discovery`
6. `npm run build:agent-skills`

Then `next build` runs.

Low-level generators (`build:search`, `build:content`, `build:shell`, `build:metadata`, `build:components`, `build:og-images`) are **not** part of prebuild. Use them directly only for targeted debugging. For search + shells + new pages without AI/OG/Blobs, use `build:shell`. Full path is `publish:content`.

## Artifact Map

### 1) public/search-index.json

Generated by: `scripts/build-search-index.mjs`

Purpose:

- canonical static index of Notion pages
- search payload consumed by the client
- source of truth for menu grouping and route metadata
- source input for redirects and edge redirect data

Read by:

- `src/lib/search.ts` (client-side search fetch)
- `src/app/layout.tsx` (header/menu data)
- `src/lib/notion-cover.ts` (cover/tag/link lookup artifacts)
- `scripts/build-content-cache.mjs` (list of pages to cache)
- `scripts/build-redirects.mjs` and `scripts/build-edge-data.mjs`

### 2) public/.notion-cache/*.json

Generated by: `scripts/build-content-cache.mjs`

Purpose:

- per-page recordMap cache for Notion pages
- used during Next production build instead of live Notion calls

Read by:

- `src/lib/notion-server.ts` when `NEXT_PHASE === "phase-production-build"`
- all static page generators that call `getBuildCachedNotionPage(...)`

Behavior:

- sequential downloads with retry/backoff
- skip existing files by default
- `--refresh-shell` to always refresh homepage, menuGroup DBs, and category hub pages (`type !== pattern`). Pattern pages stay skip-if-exists.
- merges patterns gallery `collection_query` into homepage cache after build
- `--force` to refresh all
- optional `--allow-failures` mode

### 3) public/components/components-metadata.json + public/components/code/*.tsx

Generated by: `scripts/build-artifacts-cache.mjs` (via `publish:content`)

Purpose:

- AI-enriched metadata layer per pattern
- generated component TSX artifacts per pattern
- generation status and manifest reports

Read by:

- optional UI enrichment paths
- debug/artifacts inspection pages

Notes:

- Local TSX under `public/components/code` is committed for `next dev` / `/debug` and as upload input.
- Production Export/Preview reads **Netlify Blobs**, not published `out/components/code` or `out/components/history` (stripped on build).
- Normal path: `npm run publish:content` (generates + uploads new seeds), then commit `public/search-index.json`, `public/components/code/`, `components-status.json`, `components-metadata.json`, and `components-manifest.json`. Do **not** commit `_*-report.json` or `seeds-manifest.json` (gitignored last-run logs / upload helper).
- Escape hatch: `PATTERN_PUBLISH_SKIP_SEEDS_UPLOAD=1` skips Blobs upload.

### 4) public/og/covers/manifest.json + CDN JPEGs

Generated by: `scripts/build-og-images.mjs` (via `publish:content`)

Purpose:

- 1200×630 letterboxed social cards for GIF/Giphy pattern covers (LinkedIn size rules)
- JPEGs live on `https://cdn.patttterns.com/og/{id}.jpg` (UI posters + `og:image`)
- Card stills stage in `.cdn-images/covers/` and publish to `https://cdn.patttterns.com/covers/{id}.jpg`
- This repo keeps only `manifest.json` (which ids have an OG card)

Notes:

- Incremental: skips when `manifest.json` source URL matches and the staged JPG exists
- `npm run publish:cdn-images` pushes `.cdn-images/` to `pabliqe/patttterns-cdn`
- See [Cover Stills CDN and Viewport Giphy](../../product-roadmaps/specs/cover-stills-cdn-and-viewport-giphy).

### 5) public/_redirects

Generated by: `scripts/build-redirects.mjs`

Purpose:

- Netlify redirect rules for high-value legacy URL patterns
- mainly folder + Notion ID -> canonical slug redirects

Notes:

- constrained to Netlify free-tier redirect limits
- non-core redirect cases are handled by edge function logic

### 6) netlify/redirect-data.json

Generated by: `scripts/build-edge-data.mjs`

Purpose:

- edge lookup maps for redirector function
- slug map and normalized Notion ID map

Read by:

- `netlify/edge-functions/redirector.ts`

### 7) .next/

Generated by: `next build`

Purpose:

- intermediate Next.js build output used before export

### 7) out/

Status in this repo:

- ignored in git
- Netlify publish target in this repo (`publish = "out"`)
- generated from `next build` when static export mode is enabled
- post-processed by `scripts/strip-components-from-out.mjs` after `next build`
- stripped output excludes component TSX/history, raw `.notion-cache`, and RSC `.txt` flight sidecars unless `KEEP_RSC_TXT=1`

RSC `.txt` sidecars are generated by Next for App Router soft navigation and prefetch. They are not markdown, page text, or OG assets. Stripping them keeps full HTML document loads working and substantially reduces deploy size, but browser consoles can show expected `_next_tree.txt?_rsc=...` or per-page `.txt` 404s during prefetch.

## Runtime Usage Summary

At runtime, the app mostly uses prebuilt static files:

- search/menu/covers from `public/search-index.json`
- pre-cached Notion recordMaps during build phase from `public/.notion-cache`
- metadata/components enrichment from `public/components/*` when local artifacts are present
- redirect maps from `public/_redirects` and edge redirect data

## Netlify Cache Persistence

Netlify cache persistence for `public/.notion-cache` is disabled in this repo.

- no build plugin restores content cache before build
- no build plugin saves content cache after build
- deploy output is produced from repository-tracked artifacts and current build inputs only

## Environment Variables (Most Relevant)

Search/build-index and Notion fetch behavior:

- `NOTION_API_KEY`
- `NOTION_TOKEN` (if needed for private content)
- `NOTION_FETCH_RETRY_ATTEMPTS`
- `NOTION_FETCH_BASE_DELAY_MS`
- `NOTION_FETCH_MAX_DELAY_MS`
- `NOTION_FETCH_TIMEOUT_MS`
- `NOTION_FAIL_FAST`

Metadata/components generation specific (local-only flow):

- `GEMINI_API_KEY`
- `PATTERN_METADATA_MODEL`
- `PATTERN_METADATA_GEMINI_TIMEOUT_MS`
- `PATTERN_METADATA_NOTION_TIMEOUT_MS`
- `PATTERN_METADATA_RETRY_ATTEMPTS`
- `PATTERN_METADATA_NOTION_DELAY_MS`
- `PATTERN_METADATA_GEMINI_DELAY_MS`

Content-cache specific:

- `NOTION_CONTENT_DELAY_MS`
- `NOTION_CONTENT_RETRY_ATTEMPTS`
- `NOTION_CONTENT_TIMEOUT_MS`
- `NOTION_CONTENT_429_DELAY_MS`

Post-build strip controls:

- `COMPONENTS_STRIP_OUT=0` skips all `out/` stripping (debug only)
- `KEEP_RSC_TXT=1` keeps Next RSC `.txt` sidecars for soft-navigation/prefetch behavior at the cost of a larger deploy

## Local Commands

Publish everything (recommended):

```bash
npm run publish:content
```

Run only search index:

```bash
npm run build:search
```

Generate/sync local AI artifacts:

```bash
npm run build:artifacts
```

Validate local AI artifacts snapshot:

```bash
npm run validate:artifacts
```

Build/update Notion content cache:

```bash
npm run build:content
```

Refresh search index, homepage / listing / category hub shells, and any new uncached pages:

```bash
npm run build:shell
```

`build:search` sets category `coverImage` from Notion **page Cover** (the database row, no children crawl). Pattern `coverImage` stays first body/Giphy image.

Re-scan **pattern body GIFs** (not category Covers) and refresh GIF OG cards:

```bash
npm run build:covers -- --ids=<id[,id…]>          # re-scan those pattern body images only
npm run build:covers -- --ids=<id> --force        # plus rebuild their OG JPEGs
npm run build:covers                              # fleet-wide body rescan (can 429)
npm run build:covers -- --force                   # fleet-wide + rebuild every GIF OG JPEG
```

Category Cover edits: `npm run build:shell` (or `publish:content`). Do not use `build:covers`.

Force-refresh all cached pages:

```bash
npm run build:content -- --force
```

Run deploy-time prebuild only:

```bash
npm run prebuild
```

## Failure Modes and Fixes

1. search-index missing

- Symptom: menu/search empty, redirect build fails
- Fix: run `npm run publish:content` or `npm run build:search`

2. notion-cache misses during build

- Symptom: `validate:content-cache` fails, or `[notion-cache] miss ...` logs and a 404 shell at the pattern URL
- Cause: `search-index.json` was committed without the matching `public/.notion-cache/{id}.json`. Pre-push/`next build` do **not** fetch Notion.
- Fix: run `npm run publish:content` (not `build:search` alone), then commit **both** the index and `.notion-cache/`

3. metadata descriptions not visible on front pages

- Symptom: pattern pages still show baseline descriptions from search-index
- Fix: run `npm run publish:content`

4. homepage grid missing new patterns

- Symptom: pattern works at `/patterns/slug` but not on homepage
- Fix: run `npm run build:shell` or `npm run publish:content`

4b. category Cover stale (homepage floats / inner hero pink, listing cards already new)

- Symptom: Notion Cover changed but `search-index.json` `coverImage` and/or category `.notion-cache` still have the old file
- Cause: category Cover is `page.cover` on the DB row; listing shells refresh it, but the index and category hub cache must too
- Fix: `npm run build:shell` (picks up `page.cover` into the index and refreshes category hub recordMaps). Do **not** run `build:covers` for this.

5. too many Notion retries/timeouts

- Symptom: slow or failing publish
- Fix: increase timeout/retry env values, keep sequential content-cache mode

6. redirect count too high

- Symptom: warning/error in redirect build
- Fix: keep only essential static redirects and rely on edge maps for scale

## Quick Mental Model

- `publish:content` — one local command for Notion + AI artifacts + OG covers **and** new Blobs seed upload
- `build-search-index` — discover and normalize content metadata
- `build-artifacts-cache` — generate AI metadata and component artifacts
- `build-content-cache` — snapshot full page content for build-time rendering
- `build:shell` — `build:search` + `build:content -- --refresh-shell` (index; homepage + menu DBs + category hubs; new pattern pages)
- `build:covers` — force-rescan **pattern** body images, then `build-og-images`. Prefer `--ids=<id[,id…]>`. Unscoped can 429. Not for category Cover changes.
- `build-og-images` — letterbox GIF covers to JPEG under `.cdn-images/og/` and update `public/og/covers/manifest.json`; `--force` ignores the source-URL skip
- `publish:cdn-images` — push `.cdn-images` into `pabliqe/patttterns-cdn` (`PATTERN_PUBLISH_SKIP_CDN_IMAGES=1` to skip)
- `prebuild` — completeness gate, then redirect/discovery plumbing (still no Notion)
- `next build` — compile app using committed artifacts
