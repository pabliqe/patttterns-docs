Deployment Guide

Platform: Netlify
Framework: Next.js (App Router, static export)
Production URL: https://patttterns.com
Last updated: September 2026

How publishing works (read this first)

Section titled “How publishing works (read this first)”

Production is a two-step process:

  1. Refresh content — pull from Notion, write cache files, build static OG JPEG covers, upload new component seeds to Blobs, commit to git
  2. Deploy site — Netlify builds static HTML from those committed files, then strips non-runtime artifacts from out/

Netlify does not call Notion during normal deploys. It reads what is already in the repo. Export/Preview reads Blobs (populated during publish:content).

Step Who runs it Output
Content publish Local: npm run publish:content Git caches + Blobs seeds for new components
Site deploy Netlify on every push to main Static site in /out

See also: Cache Pipeline · Publishing Notion content

Netlify build settings

Section titled “Netlify build settings”

Configured in netlify.toml:

Setting Value
Build command npm ci && npm run build
Publish directory out
Notion during build Never — content is committed to git before deploy

Do not set publish directory to .next — production uses static export to /out.

Local development

Section titled “Local development”

npm run dev talks to Notion directly. Production uses committed cache files only — so you can see patterns locally that are not on the live site until you refresh and commit.

Simulate a production build locally

Section titled “Simulate a production build locally”

This matches Netlify: prebuild regenerates redirects and edge data, then next build exports static pages from committed public/search-index.json, public/.notion-cache/, and public/og/covers/manifest.json. Cover JPEGs are requested from cdn.patttterns.com. The build then strips out/components/code, out/components/history, raw out/.notion-cache, and RSC .txt flight sidecars.

Local (.env.local)

Section titled “Local (.env.local)”

Copy from .env.example. Minimum for content refresh:

  • NOTION_API_KEY
  • NOTION_TOKEN (if private pages need it)

Database IDs default in site.config.mjs; override with env vars if needed.

Never commit secrets to git.

Troubleshooting

Section titled “Troubleshooting”

New pattern works locally but not on production

Section titled “New pattern works locally but not on production”
  1. Run npm run publish:content locally.
  2. Commit public/search-index.json, public/.notion-cache/, public/components/, and public/og/covers/manifest.json.
  3. Push to main.

Local dev uses live Notion; production only sees committed cache.

Console shows _next_tree.txt?_rsc=... or page .txt 404s

Section titled “Console shows _next_tree.txt?_rsc=... or page .txt 404s”

These are expected when the post-build strip removes Next App Router RSC flight sidecars to keep out/ small. They affect soft-navigation prefetch noise, not OG images, search data, or full HTML page loads. Set KEEP_RSC_TXT=1 npm run build only when you need to keep the old soft-navigation payloads for debugging or comparison.

Pattern in search but 404 on its page

Section titled “Pattern in search but 404 on its page”

The slug must exist in search-index.json and have a matching file in public/.notion-cache/{id}.json. npm run build / pre-push never call Notion — they only prerender committed cache. Run npm run publish:content and commit both artifacts. validate:content-cache now fails the build if they drift.

Pattern on /patterns but missing from homepage grid

Section titled “Pattern on /patterns but missing from homepage grid”

Run npm run publish:content — it refreshes shell pages and merges the patterns gallery into the homepage cache.

Build fails on Netlify

Section titled “Build fails on Netlify”
  1. Check deploy logs in Netlify dashboard.
  2. Reproduce locally: npm run build.
  3. Common causes: TypeScript errors, missing cache file for an index entry, redirect validation failure.

[notion-cache] miss during build

Section titled “[notion-cache] miss during build”

Run npm run publish:content, then commit the new .notion-cache files.

Rollback

Section titled “Rollback”

Fast: Netlify dashboard → Deploys → pick a previous successful deploy → Publish deploy.

Git: git revert <commit> and push — Netlify rebuilds from the reverted tree.

Release checklist

Section titled “Release checklist”

Code release

  • npm run build passes
  • npm run lint passes
  • Push to main; confirm Netlify deploy succeeds

Content release (new/updated Notion patterns)

  • npm run publish:content
  • Commit public/search-index.json + public/.notion-cache/ + public/components/
  • Push to main; verify pattern on production
