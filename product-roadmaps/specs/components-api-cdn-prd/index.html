Components API CDN PRD

Status: Phase 1–2 implemented on PATTTTERNS (same Netlify site). Phase 3–4 not started.
Canonical doc for the chat “Plan” — do not maintain a second copy; update this file instead.

Prompting contract (1st gen vs regenerate, image/metadata gaps): Components Generation Prompting.

Objective

Section titled “Objective”

Move component TSX out of the main PATTTTERNS out/ build into a headless API + CDN. All user-facing UI stays on PATTTTERNS. Generations must not rebuild the main site.

Locked split

Section titled “Locked split”
Layer Lives where Owns
All user-facing UI PATTTTERNS always Pattern Export, previewer, /debug, login modal
API + CDN Headless backend (Phase 1: Netlify Functions + Blobs on this site; later extractable to its own repo) Durable TSX, versions, authors, Gemini generate/regenerate

There is no separate components website.

Goals

Section titled “Goals”
  1. Debug admins can generate new components.
  2. Components may use primary or secondary pattern image; one seed per pattern as the origin TSX (replaceable via promote-to-seed).
  3. Versions under a pattern are grouped and stamped with author name/avatar.
  4. PATTTTERNS does not rebuild on every generation.
  5. Backend may be Functions+Blobs now, or a dedicated repo/CI later — same API contract.

Problem

Section titled “Problem”

Today generated TSX starts as a build artifact of the main site:

  • Written by scripts/build-components-cache.mjs into public/components/code/
  • Committed in-repo, then copied into Netlify out/ via Next static export (Phase 2 now strips code/ + history/ from publish)
  • Preview/Export already HTTP-fetch by URL (usePatternCode) — that part was fine

Debug regenerate APIs that write the local filesystem 404 on Netlify because out/ is immutable.

So the blocker is not “preview can’t leave out/” — preview already loads by URL. The blocker is mutable generation with durable storage, while the main site remains a static CDN publish. Direction: component TSX leaves the main publish; UI stays on PATTTTERNS (no separate components website).

Architecture

Section titled “Architecture”

Data model (per pattern)

Section titled “Data model (per pattern)”
  • Seed is the origin TSX. Promote-to-seed overwrites it from a vN. Hide/delete of seed is allowed when another visible version remains.
  • The last visible version cannot be hidden or deleted.
  • Regenerates use the live visible baseline (active, then newest visible) as prompt context and a lower thinking budget.

API contract

Section titled “API contract”

Base (Phase 1): /.netlify/functions/components-api

Method Query / body Purpose
GET op=whoami Confirm debug-admin JWT (admin auth required)
GET op=list All visible generations for /debug (admin auth required)
GET op=versions&id= Versions for one pattern
GET op=generation-models Seed + regenerate Gemini model config from runtime env
GET op=active&id= Active TSX (text/plain)
GET op=code&id=&version= Specific version TSX
POST op=generate + JSON { id, intent?: iterate|fresh, userPrompt?, imageRole? } fresh = PROMPT A from metadata (no TSX). iterate (default) = PROMPT B on live TSX. Writes vN (admin auth)
POST op=rebuild + JSON { id, baselineVersionId? } Normalize existing TSX → new vN + active (admin auth; no Gemini)
POST op=put-seed + JSON { id, code, title?, slug?, coverImage?, force? } Bootstrap seed without Gemini; force overwrites (admin auth)
POST op=publish + JSON { id, code, kind?, seedCode?, versionId? } Push local TSX: new seed (if missing) or new active vN (admin auth; never overwrites seed)
POST op=promote-seed + JSON { id, versionId, confirm } Copy vN onto seed.tsx, keep vN, set active to seed (admin auth)
POST op=hide + JSON { id, versionId, confirm, confirmAgain } Soft-hide any version including seed; refuses last visible (admin auth)
POST op=delete + JSON { id, versionId, confirm, confirmAgain } Hard-delete blob + index row including seed; refuses last visible (admin auth)

Image gap

Section titled “Image gap”

Search-index today has only coverImage (primary). Secondary image requires a later index/Notion enrichment. Phase 1 uses primary only.

Phased delivery

Section titled “Phased delivery”

Phase 1 — Same-site Functions + Blobs ✅

Section titled “Phase 1 — Same-site Functions + Blobs ✅”
  • Auth-gated Netlify Function API
  • Netlify Blobs for TSX + version indexes
  • Bootstrap seed from existing /components/code/{id}.tsx on first generate if missing in Blobs
  • Wire /debug regenerate/rebuild/publish/hide/list to the Function
  • Main Export may still fall back to static TSX until Phase 2

Phase 2 — Decouple main out/ ✅ closed

Section titled “Phase 2 — Decouple main out/ ✅ closed”

Checklist:

  • usePatternCode uses Components API only in production; static/debug fallbacks remain for next dev
  • Postbuild strips out/components/code and out/components/history (scripts/strip-components-from-out.mjs)
  • Artifact badges use components-status.json (server + client), not published TSX
  • op=put-seed + migrate script bootstrap Blobs without Gemini
  • Optional COMPONENTS_SEEDS_BASE_URL for transitional seed fetch after strip
  • Clean local pipeline: first-gen → put-seed / migrate (Components Seeds Pipeline)

Ops note: Prefer npm run publish:content (includes components:seeds:upload) via Netlify CLI (netlify login + netlify link) so new seeds land in Blobs without a Supabase token. Targeted ops: npm run components:seeds:upload -- --ids=<id>. Optional --via-api keeps op=put-seed. See Components Seeds Pipeline.

Repo keeps public/components/code for local generation cache and migrate input; publish dir does not.

Phase 3 — Secondary image + grouped UX

Section titled “Phase 3 — Secondary image + grouped UX”
  • Secondary image in index
  • /debug grouped-by-pattern author filters

Phase 4 — Optional extract

Section titled “Phase 4 — Optional extract”
  • Move Function/Blobs (or equivalent) into a dedicated components API repo/CDN host without changing PATTTTERNS UI

Prompt contract: Components Generation Prompting.
Click-only regenerate quality (shipped): Plan Status.

PRD prompt

Section titled “PRD prompt”

Build a headless Components API/CDN. PATTTTERNS remains the only user-facing UI. Debug admins create a seed origin and later regenerates (visible baseline as context; primary/secondary image). Versions grouped by patternId with author attribution. Hide is soft; delete is hard; both refuse the last visible version. Promote-to-seed replaces a bad origin. PATTTTERNS must not ship TSX in out/ long-term and must not rebuild on generate. Do not build a separate components website. See Debug Admin Access for /debug authorization.

Success metrics

Section titled “Success metrics”
  • Regenerate works on Netlify without a main-site rebuild
  • New versions persist in Blobs (not out/)
  • Seeds remain available; authors recorded
  • Export/Preview load active TSX from the Components API (no TSX in published out/)
